3. FULL DOCUMENTED FFGLORY PROVIDER API (https://ffglory.pro)
====================================================================
ALL calls to `https://ffglory.pro` MUST run strictly on the Node.js/Express backend server (NEVER expose API keys or passwords in frontend JS).
Authentication Rules:
- Send `api_key` query param (`PROVIDER_API_KEY`) AND `x-api-key` header (`PROVIDER_MASTER_KEY`), EXCEPT:
  - `GET /api/pricing` (public, no keys required)
  - `POST /api/auth/signup` (`x-api-key` header only; skips CAPTCHA)
Implement ALL 18 documented endpoints & actions:
1. `GET /api/auth/me` -> Live provider username, role, `basic_credits`, `premium_credits`, `max_groups`
2. `POST /api/auth/signup` -> `{ username, password }` (handles HTTP 409)
3. `GET /api/pricing` -> `basic_credit_usd`, `premium_credit_usd`, `regions[]` (`id`, `region_name`, `region_code`, `tier`, `enabled`)
4. `POST /api/client/auto-clan-group` -> `{ region, clan_id }` (returns `success`, `group_id`, `bot_count`; handles 402/403/409)
5. `GET /api/client/my-groups` -> Active groups (`group_id`, `clan_id`, `region`, `status`, `container_count`, `running_count`, `uptime`)
6. `POST /api/client/group-action` -> `{ action, group_id }` for `"restart"`, `"stop"`, `"delete"` (permanent), `"get-glory"`, `"get-clan-info"`
7. `POST /api/client/create-coupon` -> `{ basic_credits (0-100), premium_credits (0-20) }` (min 1 total, max 100 active)
8. `GET /api/client/my-coupons`
9. `GET /api/client/redeemed-coupons`
10. `POST /api/client/redeem-coupon` -> `{ code }` (`XXXX-XXXX-XXXX`, rate limit 5 attempts / 60s)
11. `POST /api/client/cancel-coupon` -> `{ code }` (active coupons only; refunds credits)
12. `GET /api/client/transactions` (last 50)
13. `POST /api/client/cancel-transaction` -> `{ transaction_id }`
14. `GET /api/client/group-history` (with `glory_snapshots[]`)
15. `GET /api/client/glory-progression?group_id=X`
16. `GET /api/client/activity-log` (last 200 events: `start`, `stop`, `delete`, `restart`, `refund`)
17. `GET /api/client/notifications` (one-time read; store fetched notifications in DB so users don't lose them)
18. Error Handling (`400`, `401`, `402`, `403`, `404`, `409`, `429`): Surface real provider errors only. Before launching a group, atomically deduct 1 website credit in the database; if the provider call fails, automatically refund 1 credit atomically and write a sanitized log entry to `api_logs` (without exposing keys).
